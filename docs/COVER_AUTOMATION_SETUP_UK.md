# Налаштування автоматичного додавання обкладинок

Ця інструкція призначена для користувача без навичок програмування.

## 1. Як працює система

У рядку нової книги на аркуші «Матеріали» з’являються поля:

- **Джерело обкладинки** — сторінка книги або прямий URL картинки;
- **Попередній перегляд** — знайдена обкладинка;
- **Підтвердити обкладинку** — checkbox;
- **Статус обкладинки** — поточний стан обробки;
- **CAT-ID обкладинки** — визначається автоматично.

Система спочатку знаходить і показує зображення. Файл потрапляє в GitHub
лише після підтвердження та появи CAT-ID.

## 2. Підтримувані посилання

Підтримуються:

- прямі JPG/JPEG, PNG та WEBP URL;
- звичайні HTML-сторінки з `og:image`;
- сторінки з `twitter:image`, `image_src` або JSON-LD `image`.

Не підтримуються:

- сторінки, що вимагають входу;
- CAPTCHA;
- зображення, доступне лише після виконання JavaScript;
- локальні й приватні мережеві адреси;
- `file://` та нестандартні HTTP-порти.

Якщо сторінка магазину не працює, вставте пряме посилання на картинку.

## 3. Підготовка GitHub token

1. Відкрийте налаштування GitHub.
2. Створіть fine-grained personal access token.
3. Дозвольте доступ лише до репозиторію `nazarijshvetz1/library-covers`.
4. Для Repository permissions встановіть **Contents: Read and write**.
5. Установіть короткий термін дії та збережіть token у надійному місці.

Не вставляйте token у Google Sheets або GitHub-файли.

## 4. Прив’язування Apps Script

1. Відкрийте потрібну Google-таблицю.
2. Виберіть **Розширення → Apps Script**.
3. Додайте в проєкт код з `apps-script/Code.gs`.
4. Не видаляйте наявний код фільтрації «Ревізії».
5. У налаштуваннях проєкту відкрийте **Script Properties**.
6. Створіть:
   - `GITHUB_TOKEN` — ваш token;
   - `GITHUB_OWNER` — `nazarijshvetz1`;
   - `GITHUB_REPO` — `library-covers`.

## 5. Встановлення полів і тригерів

Після злиття workflow у `main`:

1. У списку функцій Apps Script виберіть `setupCoverAutomation`.
2. Натисніть **Run**.
3. Надайте дозволи.
4. Поверніться до таблиці й перезавантажте сторінку.

Функція додає поля праворуч від чинного блоку, встановлює checkbox,
формулу preview та два тригери. Повторний запуск не дублює їх.

## 6. Звичайне використання

1. Заповніть дані нової книги.
2. Вставте URL у «Джерело обкладинки».
3. Дочекайтеся статусу **Очікує підтвердження**.
4. Перевірте preview.
5. Установіть checkbox.
6. Якщо CAT-ID ще створюється, з’явиться статус
   **Очікується створення CAT-ID**.
7. Після завершення з’явиться **Обкладинку додано**.

Кінцевий URL записується лише в чинне поле «Обкладинка (URL)».

## 7. Dry run

1. Відкрийте вкладку **Actions** у GitHub.
2. Виберіть **Import library cover**.
3. Натисніть **Run workflow**.
4. Уведіть тестовий CAT-ID, URL і новий UUID.
5. Залиште `dry_run=true`.

Dry run завантажує й перевіряє зображення, але не створює файл у `covers/`.

## 8. Заміна неправильної обкладинки

Запустіть workflow вручну з параметрами:

- `mode=commit`;
- правильний CAT-ID;
- нове джерело;
- `overwrite=true`;
- `dry_run=false`.

Заміна створить окремий Git commit. Через кеш raw GitHub або Google Sheets
оновлення картинки інколи відображається не миттєво.

## 9. Статуси

- **Очікує підтвердження** — preview готовий;
- **Надіслано на обробку** — запит прийнято Apps Script;
- **Обробляється** — очікується status JSON;
- **Обкладинку додано** — готовий GitHub URL записано;
- **Файл уже існує** — файл не перезаписано;
- **Не знайдено зображення** — сторінка не містить підтримуваного image metadata;
- **Посилання недоступне** — URL помилковий, закритий або небезпечний;
- **Непідтримуваний формат** — завантажений вміст не є зображенням;
- **Потрібна пряма фотографія** — файл надто великий або сторінка не підходить;
- **Помилка завантаження** — інша технічна помилка.

## 10. Резервне ручне додавання фотографії

Якщо жоден URL не працює:

1. Підготуйте фотографію обкладинки.
2. Конвертуйте її в JPG.
3. Назвіть `CAT-XXXX.jpg`.
4. У GitHub відкрийте папку `covers/` і виберіть **Add file → Upload files**.
5. Перевірте raw URL.
6. Запишіть його в «Обкладинка (URL)» для відповідного нового матеріалу.

Не замінюйте наявний файл без перевірки CAT-ID.

## 11. Відкликання або заміна token

1. Відкличте старий token у налаштуваннях GitHub.
2. Створіть новий із доступом лише до `library-covers`.
3. Замініть лише значення `GITHUB_TOKEN` у Script Properties.
4. Не потрібно змінювати код або повторно створювати колонки.
